# Skill Usage Log Reviewer

Аудит коллекции установленных скилов Claude с чеклистом деактивации для поддержания лёгкого портфолио.

---

## Обзор

Skill Usage Log Reviewer анализирует установленные скилы Claude, выявляет неиспользуемые и дублирующие друг друга, и генерирует структурированный отчёт с чеклистом деактивации. По мере роста коллекции каждый установленный скил добавляет токены к каждой сессии — даже те, которые никогда не вызываются. Используйте этот скил, когда список установленных скилов вырос до 10 и более, сессии кажутся медленными или перегруженными, либо вы хотите провести плановую ревизию портфолио скилов.

---

## Требования

- Список установленных скилов (вставить из настроек, вывод `ls` или описание)
- Опционально: краткие заметки об использовании каждого скила ("использую ежедневно", "попробовал один раз", "ни разу не запускал")
- Дополнительные инструменты или файлы не нужны

---

## Как использовать

1. **Подготовьте список скилов**
   - Откройте настройки Claude и посмотрите список активных скилов, или вставьте имена установленных скилов
   - По желанию добавьте короткую пометку рядом с каждым: "использую еженедельно", "установлен, но не запускал" и т.п.

2. **Активируйте скил**
   - Напишите: "Аудит скилов" или "Обзор использования скилов"
   - По-английски: "Audit my skills" или "Skill usage review"

3. **Ответьте на вопросы об использовании (если потребуется)**
   - Скил спросит, какие скилы вы используете ежедневно / еженедельно / ежемесячно / никогда
   - Вопросы задаются пакетами — отвечайте сразу на группы из 5–8 скилов

4. **Изучите отчёт аудита**
   - Получите таблицу с вердиктами Оставить / Пересмотреть / Деактивировать для каждого скила
   - Используйте Чеклист деактивации, чтобы удалить неиспользуемые скилы из настроек

## Примеры

### Пример 1: Чистка коллекции из 12 скилов

**Входные данные:**
```
morning-standup-brief-generator — использую каждый день
session-handoff-composer — использую еженедельно
weekly-competitor-tracker — установлен 3 недели назад, ни разу не запустил
meeting-prep-briefer — использую иногда
one-to-one-prep — запустил один раз
context-window-health-check — использую еженедельно
retro-pattern-analyzer — ни разу не использовал
okr-progress-narrator — установлен, попробовал один раз
team-update-aggregator — использую раз в месяц
weekly-ai-workflow-review — использую еженедельно
delegation-brief — установлен, не уверен что делает
feature-guide — использовал несколько раз
```

**Действие:** Скил классифицирует уровни использования, обнаруживает, что meeting-prep-briefer и one-to-one-prep пересекаются по назначению, помечает 4 скила как «Деактивировать».

**Результат:**
```markdown
# Отчёт аудита скилов
**Дата:** 2026-05-05
**Всего проверено скилов:** 12
**Оставить:** 6 | **Пересмотреть:** 2 | **Деактивировать:** 4

## Итог
Коллекция умеренно перегружена — 4 скила можно деактивировать сразу, сэкономив ~1 200 токенов за сессию.

## Таблица аудита

| Скил | Вердикт | Причина |
|------|---------|---------|
| weekly-competitor-tracker | ❌ Деактивировать | Ни разу не использован за 3 недели |
| retro-pattern-analyzer | ❌ Деактивировать | Никогда не запускался; узкий кейс |
| okr-progress-narrator | ❌ Деактивировать | Попробован раз; перекрывается с team-update-aggregator |
| delegation-brief | ❌ Деактивировать | Ни разу не вызван; назначение непонятно |
| one-to-one-prep | ⚠️ Пересмотреть | Пересекается с meeting-prep-briefer; использован один раз |
...
```

### Пример 2: Проверка небольшой коллекции

**Входные данные:**
```
prompt-library-curator, session-handoff-composer, context-window-health-check, feature-guide, report-analyzer
```

**Действие:** Скил проверяет 5 скилов, обнаруживает, что все используются иногда или регулярно, дубликатов нет.

**Результат:**
```markdown
# Отчёт аудита скилов
**Дата:** 2026-05-05
**Всего проверено:** 5
**Оставить:** 4 | **Пересмотреть:** 1 | **Деактивировать:** 0

## Итог
Коллекция в порядке. Деактивация не требуется.

## Чеклист деактивации
Скилов для деактивации нет.

## Заметки
Коллекция небольшая — деактивация не обязательна. Оставляйте только то, что реально вызываете.
```
