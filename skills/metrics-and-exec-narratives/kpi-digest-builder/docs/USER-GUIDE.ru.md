# KPI Digest Builder — Руководство пользователя

Как использовать KPI Digest Builder для превращения файлов с метриками в структурированный еженедельный снапшот.

---

## Быстрый старт

Самый быстрый способ получить KPI дайджест:

1. Поместите файл с метриками (или два файла — текущая и прошлая неделя) в рабочую папку Cowork
2. Напишите: «Собери KPI дайджест» — или укажите конкретные файлы: «Собери KPI дайджест из metrics.md и metrics-prev.md»
3. Получите таблицу снапшота с дельтой и трендом, а также краткое резюме из 2–3 предложений

**Результат:** Готовый к вставке еженедельный KPI дайджест с колонками: Предыдущее / Текущее / Δ / Δ% / Тренд.

**Время:** ~2 минуты

---

## Сценарии

### Сценарий 1: Еженедельный статус-отчёт для руководства

**Ситуация:**
Вы продакт-менеджер и отслеживаете 6–8 метрик каждую неделю (выручка, активные пользователи, churn, NPS, тикеты поддержки). Вы ведёте простой markdown-файл, куда вставляете цифры в конце каждой недели. Каждый понедельник нужно отправить апдейт по метрикам руководству — сейчас вы копируете числа и считаете дельты вручную.

**Что делать:**

1. Держите два markdown-файла в рабочей папке:
   - `metrics-current.md` — цифры за эту неделю
   - `metrics-previous.md` — цифры за прошлую неделю (или переименуйте файл прошлой недели)
   - Формат может быть простым: `- Выручка: 45 000` или markdown-таблица

2. Скажите: «Собери KPI дайджест из metrics-current.md и metrics-previous.md»
   - Claude читает оба файла, сопоставляет названия метрик и рассчитывает дельты автоматически

3. Проверьте результат
   - Просмотрите таблицу KPI на предмет неожиданных изменений
   - Прочитайте Резюме — в нём выделены 2–3 наиболее значительных изменения
   - Проверьте Примечания на предмет флагов (например, несовпадение названия метрики между файлами)

4. Скопируйте результат в письмо или Slack
   - Полная таблица — для тех, кто хочет детали
   - Абзац Резюме — для руководителей, которым нужна краткая сводка

**Ожидаемый результат:**

Вы получаете отформатированную KPI-таблицу со всеми метриками и рассчитанными дельтами — без арифметики с вашей стороны. Резюме даёт готовый абзац для раздела «Главное» в вашем отчёте. То, что раньше занимало 10–15 минут ручной работы, теперь занимает 2 минуты.

**Почему это работает:** Вы продолжаете вести файлы с метриками в привычном формате. Скилл адаптируется к вашему формату, а не наоборот.

### Сценарий 2: Снапшот из CSV-выгрузки дашборда

**Ситуация:**
Вы руководитель операций. Каждую пятницу ваш аналитический инструмент (Amplitude, GA или кастомный отчёт) позволяет выгрузить CSV с KPI этой и прошлой недели рядом. Нужно превратить этот «сырой» CSV в читаемый дайджест, чтобы поделиться с руководителем до конца рабочего дня.

**Что делать:**

1. Выгрузите CSV из дашборда и поместите в папку Cowork
   - В CSV должна быть колонка с названиями KPI и две колонки значений (например, «Прошлая неделя» и «Текущая неделя»)
   - Названия заголовков не обязаны быть точными — скилл определяет текущее и предыдущее из контекста

2. Скажите: «Еженедельный снапшот KPI из export.csv»
   - Claude читает CSV, сопоставляет колонки, нормализует значения (убирает $, %, запятые)
   - Рассчитывает дельты для всех строк

3. Просмотрите дайджест
   - В разделе Примечания будут перечислены все нормализации (например, «$38 000» → «38000»)
   - Если KPI имел значение 0 на прошлой неделе, Δ% будет отмечен «—» во избежание деления на ноль

4. Поделитесь дайджестом
   - Перешлите markdown-результат руководителю или вставьте в еженедельный операционный отчёт
   - Используйте трендовые стрелки (↑ ↓ →) для быстрого визуального обзора в Slack

**Ожидаемый результат:**

Чистая таблица KPI, построенная прямо из CSV — с дельтой и трендом для каждой строки. Метрики подписаны ровно так, как в выгрузке (заголовки колонок сохранены). Любые крайние случаи (нулевые значения, особенности форматирования) отмечены в Примечаниях.

**Почему это работает:** Не нужно чистить CSV или строить формулы. Скилл читает файл напрямую и обрабатывает нормализацию — вы просто вставляете результат.

### Сценарий 3: Один файл с двумя периодами

**Ситуация:**
Вы тимлид и ведёте один скользящий файл с метриками. Каждую неделю добавляете новый раздел с текущими данными, оставляя раздел прошлой недели выше. Хотите получать дайджест без создания отдельных файлов каждую неделю.

**Что делать:**

1. Структурируйте файл с чёткими датовыми разделами:
   ```
   ## Неделя 2026-04-28
   - Выручка: 40 000
   - DAU: 9 200

   ## Неделя 2026-05-05
   - Выручка: 45 000
   - DAU: 9 800
   ```

2. Скажите: «Собери KPI дайджест из my-metrics.md»
   - Claude определяет два наиболее свежих датовых раздела
   - Использует более поздний как Текущее, более ранний как Предыдущее

3. Если файл содержит более двух разделов, Claude использует только два последних и отмечает это в Резюме

**Ожидаемый результат:**

Дайджест из одного файла — без необходимости вести два отдельных. Скилл сам определяет, какой раздел текущий, а какой предыдущий. Вы ведёте один документ; дайджест строит сравнение автоматически.

**Почему это работает:** Скилл адаптируется к вашей существующей структуре файлов, включая скользящие трекеры в одном документе.

## Советы

### Совет 1: Используйте одинаковые названия KPI в разных файлах

Скилл сопоставляет метрики между «текущим» и «предыдущим» по названию. Если одну неделю метрика называется «Выручка», а следующую — «Месячная выручка», скилл не сопоставит их и выведет как отдельные строки. Используйте одно и то же название каждую неделю.

**Совет профи:** Если в результате есть две строки, похожие на одну метрику с разными названиями, раздел Примечания отметит их как возможный дубликат — используйте это как сигнал для стандартизации.

### Совет 2: Любой формат работает — главное, чтобы он был единообразным

Скилл читает списки с дефисами, markdown-таблицы и CSV-выгрузки. Конкретный формат не важен. Важна последовательность: используйте одну и ту же структуру из недели в неделю, чтобы названия и позиции метрик совпадали. Простой список (`- Выручка: 45 000`) работает так же хорошо, как полная markdown-таблица.

### Совет 3: Используйте абзац Резюме напрямую в отчётах

Резюме из 2–3 предложений написано на деловом языке — его можно вставить в раздел «Главное» отчёта или письма руководству без правок. Если в резюме не отражена метрика, которая вам важна, упомяните её в запросе: «Собери KPI дайджест из metrics.md — обрати внимание на динамику NPS». Скилл учтёт это в резюме.
