# Release Notes Generator

Превращает plain-language итоги спринта в готовые пользовательские release notes — без git, без CLI, без технических знаний.

Напишите итоги спринта в markdown-файл в привычном формате и получите 4 готовых версии: changelog-запись, email-анонс, in-app уведомление и пост в соцсети.

---

## Требования

- Файл с итогами спринта или продуктовыми обновлениями (`.md` или `.txt`) в рабочей папке Cowork
- Подходит для: ретроспективных заметок, описания фич, handoff-документов, краткого перечня изменений
- API-ключи, git-доступ и разработческие инструменты не нужны

---

## Как использовать

1. Напишите итоги спринта или описание обновлений в файл `.md` или `.txt` (обычный язык, без специального формата)
2. Положите файл в рабочую папку Cowork
3. Запустите скил одной из фраз ниже
4. Claude прочитает файл, отфильтрует внутренние/технические пункты и сгенерирует 4 формата
5. Скопируйте нужный формат и вставьте куда нужно

---

## Примеры

**Пример 1: Итоги спринта → 4 готовых формата**

> «Сгенерируй release notes из sprint-23-results.md»

Claude читает файл, фильтрует пункты «миграция базы данных» и «рефактор модуля авторизации» (не пользовательские) и генерирует: changelog-запись для `v2.4.0`, email с темой «Спринт 23: новые фильтры в отчётах, ускоренный экспорт CSV и небольшое исправление», push-уведомление «Новое в Отчётах: 3 фильтра + быстрый экспорт. Попробуйте →» и пост для LinkedIn, открывающийся: «Раздел Отчётов стал значительно удобнее».

**Пример 2: Хотфикс-релиз**

> «Напиши release notes из hotfix-notes.md»

Claude определяет контекст хотфикса по имени файла, адаптирует тон всех 4 форматов под «сначала успокоить» и генерирует push-уведомление: «Исправлено: ошибка входа у части пользователей. Всё работает в штатном режиме.»

## Что скил делает и чего не делает

**Делает:**
- Читает plain-text файлы `.md` или `.txt` — специальный формат не нужен
- Фильтрует внутренние/технические пункты (рефакторинг, инфраструктура) и отдельно перечисляет их
- Генерирует 4 формата из одного источника: changelog, email, push-уведомление, пост в соцсети
- Адаптирует тон для хотфикс/патч-релизов (сначала успокоить)
- Работает только с локальными файлами — без git, без API-запросов

**Не делает:**
- Не работает с `.docx` и `.pdf` (сначала экспортируйте в `.txt`)
- Не подтягивает данные из git-истории или Jira/Linear (только файловый ввод)
- Не публикует автоматически ни в какой канал (формат copy-paste)
- Не генерирует блог-пост автоматически (предлагает добавить после 4 стандартных форматов)
