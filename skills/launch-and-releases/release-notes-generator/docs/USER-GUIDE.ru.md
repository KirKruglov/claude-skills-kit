# Руководство пользователя: Release Notes Generator

## Быстрый старт

Самый короткий путь к готовым release notes:

1. Напишите итоги спринта или описание обновлений в файл `.md` или `.txt` — обычный язык, специальная структура не нужна
2. Положите файл в рабочую папку Cowork
3. Скажите: «Сгенерируй release notes из [имя файла]»
4. Claude отфильтрует технические пункты, отформатирует и выдаст 4 готовых версии

**Результат:** Changelog-запись, email, push-уведомление и пост для соцсети — всё готово к копированию.

**Время:** ~3 минуты

---

## Что писать во входном файле

Специального формата нет. Пишите так, как вы обычно ведёте заметки по спринту. Примеры того, что работает:

**Минимальный вариант (список):**
```
Спринт 23 — v2.4.0 — май 2026

- Добавили 3 новых фильтра в разделе Отчёты
- Ускорили экспорт в CSV на 40%
- Исправили ошибку входа для SSO-пользователей
- Рефакторинг модуля авторизации (внутреннее)
- Обновили CI-пайплайн (внутреннее)
```

**Подробный вариант (текст + список):**
```
# Обновление продукта — май 2026

В этом спринте сосредоточились на разделе Отчёты и закрыли давнюю проблему с SSO.

Новые возможности:
- Три новых типа фильтров: диапазон дат, тег, статус
- Пакетный экспорт в CSV стал быстрее на 40%

Исправления:
- Исправлено: пользователи с SSO видели ошибку при первом входе после сброса пароля

Внутреннее (не для release notes):
- Рефакторинг модуля авторизации
- Перенос таблицы пользователей на новую схему
```

Оба варианта дают одинаковое качество результата. Claude сам разберётся, что пользовательское, а что нет.

## Сценарии

### Сценарий 1: Стандартный релиз — рассылка по каналам

**Ситуация:** Спринт 23 завершён. Есть список того, что вышло. Нужно сообщить клиентам через email и push, опубликовать пост в LinkedIn и обновить CHANGELOG.md.

**Что делать:**
1. Положите файл с итогами спринта в рабочую папку (`sprint-23.md`)
2. Скажите: «Сгенерируй release notes из sprint-23.md»
3. Claude читает файл, фильтрует внутренние пункты, генерирует все 4 формата
4. Скопируйте changelog-запись → вставьте в CHANGELOG.md
5. Скопируйте email → вставьте в почтовый инструмент, проверьте, отправьте
6. Скопируйте push-уведомление → вставьте в инструмент in-app уведомлений
7. Скопируйте пост → вставьте в LinkedIn/X, проверьте, опубликуйте

**Ожидаемый результат:** Четыре формата за один прогон. В секции «Внутренние изменения» — список того, что Claude исключил. Проверьте, что список корректен.

---

### Сценарий 2: Хотфикс — быстро и успокаивающе

**Ситуация:** Вы выпустили хотфикс для ошибки входа у SSO-пользователей. Нужно сообщить быстро и убедительно — сообщение должно начинаться с «это исправлено», а не «вот что нового».

**Что делать:**
1. Напишите короткий файл `hotfix-2026-05-12.md` с одной-двумя строками:
   ```
   Хотфикс — 12 мая 2026
   Исправлено: ошибка входа для SSO-пользователей после сброса пароля
   ```
2. Скажите: «Напиши release notes из hotfix-2026-05-12.md»
3. Claude определяет контекст хотфикса и адаптирует тон всех 4 форматов

**Ожидаемый результат:**
- Тема письма: «Исправлено: ошибка входа для SSO-пользователей»
- Письмо открывается: «Мы устранили ошибку входа...»
- Push: «Исправлено: ошибка входа для SSO-пользователей — всё работает в штатном режиме»
- Пост: «Небольшое обновление: исправили ошибку входа для SSO-пользователей. Всё в норме.»

### Сценарий 3: Большой релиз — много изменений

**Ситуация:** Закрылся квартал, вышло 15 фич. Файл с итогами спринта длинный.

**Что делать:**
1. Подготовьте `q2-release.md` со всеми изменениями, сгруппированными по тематике
2. Скажите: «Сгенерируй release notes из q2-release.md»
3. Claude генерирует все 4 формата, выделяет главные хайлайты и кратко суммирует остальное
4. Claude добавит: «Похоже, это крупный релиз — возможно, стоит написать отдельный блог-пост. Написать вступительный абзац?» — согласитесь, если нужно

**Ожидаемый результат:** Все 4 формата пропорциональны масштабу релиза; email охватывает топ-3–4 хайлайта с пометкой «и многое другое»; пост начинается с главной фичи релиза.

## Советы

**Оставьте внутренние пункты в файле — Claude отфильтрует сам.** Не нужно заранее чистить заметки. Помечайте технические пункты «(внутреннее)» или оставьте как есть — Claude классифицирует каждый пункт и отдельно перечислит исключённые, чтобы вы могли проверить.

**Называйте файл с номером версии или спринта.** Файлы вида `sprint-23.md` или `v2.4.0-release.md` позволяют Claude автоматически заполнить заголовок changelog без уточняющих вопросов.

**Для хотфиксов включите слово "hotfix" или "patch" в имя файла.** Это активирует адаптацию тона «сначала успокоить» во всех форматах.

**Push-уведомление — самый сложный формат для написания.** Claude укладывается в 160 символов, но если результат слишком общий, скажите: «Сделай push более конкретным про [название фичи]». Точечные правки работают хорошо.

**Пост для соцсети готов к публикации — но проверьте его.** Claude не использует эмодзи по умолчанию. Если ваш бренд их использует, скажите: «Добавь подходящие эмодзи к посту для соцсети» — Claude исправит.
