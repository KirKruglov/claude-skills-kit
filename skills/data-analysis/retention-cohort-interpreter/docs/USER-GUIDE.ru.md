# Руководство пользователя: Retention Cohort Interpreter

Как получать полезные выводы из данных когортного удержания с помощью простых текстовых команд.

---

## Быстрый старт

Самый быстрый способ получить диагноз удержания:

1. Скопируйте таблицу удержания из вашего аналитического инструмента (Amplitude, Mixpanel, Google Sheets и т.д.)
2. Напишите: "Проанализируй таблицу удержания" и вставьте таблицу
3. Получите структурированный отчёт: здоровье кривой, точки отвала, гипотезы, следующие шаги

**Результат:** Понятный диагноз, который можно сразу вынести на продуктовый ревью или в отчёт для инвестора.

**Время:** ~3 минуты

---

## Сценарии

### Сценарий 1: Еженедельное ревью метрик — выявление проблемы с удержанием

**Ситуация:**
Вы продакт-менеджер, готовитесь к еженедельному ревью метрик. Открываете когортную таблицу в Amplitude и замечаете, что последние три когорты выглядят хуже предыдущих, но непонятно — это тренд или шум. Нужно быстро понять: эскалировать или подождать ещё неделю.

**Что делать:**

1. Экспортируйте таблицу удержания из Amplitude (или скопируйте из дашборда)
   - Возьмите 3–6 последних когорт и все доступные периоды
   - Скопируйте как CSV или вставьте в виде текстовой таблицы

2. Запустите скил: "Проанализируй таблицу удержания" и вставьте таблицу
   - При необходимости добавьте контекст: "Это B2C мобильное приложение" или "Фокус на D7"

3. Изучите блок «Здоровье кривой»
   - **Здоровая** → решение «наблюдать» обосновано
   - **Требует работы** / **Критическая** → эскалация оправдана; используйте гипотезы для формулировки повестки

4. Используйте гипотезы для структурирования обсуждения на ревью
   - Поделитесь топ-2 гипотезами с командой
   - Из блока «Следующие шаги» сформируйте задачи для расследования

**Ожидаемый результат:**

Структурированный диагноз с чёткой меткой здоровья, конкретным периодом концентрации оттока и 3 тестируемыми гипотезами, привязанными к этому окну.

**Почему это работает:** Вместо субъективного разглядывания цифр вы получаете фреймворк с конкретными значениями падений, сравнением с бенчмарком и готовыми гипотезами. Ревью становится сфокусированным, а решения — обоснованными.

### Сценарий 2: Отчёт для инвестора — как представить здоровье удержания

**Ситуация:**
Вы фаундер, готовите ежемесячный апдейт для инвесторов. Продукт на рынке 9 месяцев, есть данные по 6 когортам. Инвесторы ожидают раздел про удержание, но вы не уверены, как сформулировать цифры и какую историю рассказать.

**Что делать:**

1. Подготовьте таблицу когортного удержания
   - Месячные когорты (M1–M6 для каждой когорты)
   - Если значения — абсолютные числа аккаунтов, это нормально — скил сам пересчитает в %

2. Напишите: "Интерпретируй когортный анализ — это B2B SaaS" и вставьте данные
   - Указание типа продукта гарантирует применение правильных бенчмарков

3. Изучите блок «Сравнение с бенчмарком»
   - Ваша кривая выше / на уровне / ниже бенчмарка — это ключевой тезис для слайда
   - Используйте конкретные цифры в презентации

4. Используйте нарратив из «Здоровья кривой» в апдейте
   - Скопируйте 1–2 предложения из этого раздела
   - Добавьте блок «Следующие шаги» — покажите, что у вас есть план

**Ожидаемый результат:**

Сравнение с бенчмарком с конкретными цифрами (например, «Ваше M3-удержание 71% выше бенчмарка B2B SaaS 65–70%»), метка здоровья и нарратив, который можно процитировать в письме инвестору.

**Почему это работает:** Инвесторы хотят видеть, что вы понимаете своё удержание и умеете его контекстуализировать. Сравнение с бенчмарком даёт объективную точку отсчёта, а нарратив избавляет инвестора от необходимости интерпретировать сырые цифры самостоятельно.

### Сценарий 3: Проверка эффекта запуска — как новый онбординг повлиял на удержание

**Ситуация:**
Вы аналитик роста. 6 недель назад команда запустила новый онбординг-флоу. Хотите понять, лучше ли удерживаются когорты, пришедшие после запуска, и есть ли ещё что доработать.

**Что делать:**

1. Сформируйте сравнительную таблицу с до- и послезапускными когортами
   - Чётко подпишите строки: "До запуска (Фев НД1)", "После запуска (Апр НД1)" и т.д.
   - Включите D1, D7, D14, D30 для каждой когорты

2. Запустите скил: "Проанализируй таблицу удержания — 15 марта запустили новый онбординг"
   - Контекст помогает скилу связать паттерн аномальной когорты с датой запуска

3. Обратите внимание на флаг об аномальных когортах
   - Если послезапускные когорты выделены как выбросы, скил проанализирует их отдельно
   - Это покажет, есть ли измеримый эффект от запуска

4. Используйте гипотезы по основному окну отвала для выявления остаточных проблем
   - Даже если новый флоу улучшил D1, на D7 всё ещё может быть просадка

**Ожидаемый результат:**

Покогортное сравнение с выделением аномальных когорт и отдельным анализом. Отчёт чётко показывает, отличаются ли послезапускные когорты, а гипотезы указывают на оставшиеся точки роста.

**Почему это работает:** Скил автоматически выделяет когорты-выбросы и разделяет их диагноз от агрегированного тренда — это позволяет атрибутировать изменения конкретному продуктовому решению без ручного анализа.

## Советы

### Совет 1: Обязательно включайте заголовки периодов

При вставке таблицы убедитесь, что заголовки столбцов присутствуют и однозначно называют периоды (D1, Week 4, Month 3 и т.д.). Без заголовков скил может неправильно вычислить межпериодные падения. Если используете нестандартные названия ("Период 1", "Период 2"), добавьте уточнение: "Периоды — месячные, Период 1 = M1."

### Совет 2: Указывайте тип продукта для точных бенчмарков

Скил определяет тип продукта по паттерну именования периодов (дневные → мобильное; месячные → SaaS), но явный контекст надёжнее. Добавить "Это B2B SaaS" или "Потребительский маркетплейс" в запрос занимает 3 секунды, но гарантирует, что сравнение с бенчмарком будет корректным — граница между «Здоровая» и «Требует работы» часто определяется именно выбором бенчмарка.

### Совет 3: Используйте гипотезы как бриф для расследования

Три гипотезы в отчёте — это готовые задачи для расследования. Скопируйте их в Notion или Telegram, назначьте владельца и дедлайн для каждой. Каждая гипотеза указывает на конкретную метрику для инструментирования, сегмент для анализа или вопрос для кастдев-интервью. Не просто читайте — действуйте.
