# Onboarding Plan 30-60-90

Создай структурированный план адаптации нового сотрудника на 30-60-90 дней со стороны руководителя — три фазы, каждая с целями, ключевыми контактами, учебными вехами и конкретным критерием успеха.

---

## Обзор

Onboarding Plan 30-60-90 генерирует поэтапный план адаптации нового сотрудника с позиции руководителя. На вход принимает описание роли и 3–5 ключевых приоритетов; на выходе — структурированный план на три фазы: Ориентация (первые 30 дней), Вклад (дни 31–60) и Владение (дни 61–90). Используй этот скилл, когда только подтвердил найм и нужно спланировать первые 90 дней нового сотрудника, хочешь создавать единообразный план адаптации для каждого нового члена команды, или проводишь онбординг без выделенного HR-специалиста или системы онбординга.

---

## Что нужно

- Название должности и уровень нового сотрудника (обязательно)
- 3–5 ключевых приоритетов или must-learn областей роли (обязательно)
- Опционально: имя нового сотрудника, дата выхода, формат работы (удалённо / гибрид / офис), контекст команды

Дополнительные инструменты и интеграции не нужны. Работает с заметками, вставленными прямо в чат Claude.

---

## Как использовать

1. **Подготовь данные**
   - Имей под рукой название должности, уровень и 3–5 ключевых приоритетов роли
   - Опционально: имя нового сотрудника, дата выхода, формат работы, ключевые коллеги

2. **Активируй скилл фразой:**
   - "Создай план адаптации 30-60-90 для [должность]"
   - "План онбординга нового сотрудника"
   - На английском: "Create a 30-60-90 day plan" or "Onboarding plan for new hire"

3. **Предоставь детали роли**
   - Вставь заметки или опиши роль и приоритеты в нескольких предложениях
   - Скилл структурирует вводные по трём фазам

4. **Получи план адаптации**
   - Получишь markdown-документ с тремя фазами, каждая из которых содержит цели, ключевые контакты, учебные вехи и критерий успеха
   - Поделись с новым сотрудником напрямую или сохрани в папке проекта

## Примеры

### Пример 1: Junior Product Manager (гибрид)

**Ввод:**
```
Роль: Junior Product Manager, уровень: Junior
Формат: Гибрид
Приоритеты: освоить процесс построения роудмапа, понять воркфлоу исследований пользователей, посещать спринт-церемонии, научиться работать в Jira и Confluence, изучить наши 3 ключевых сегмента клиентов
```

**Вывод (фрагмент — Фаза 1):**
```markdown
# План адаптации: Junior Product Manager — Новый сотрудник

**Дата выхода:** TBD
**Формат работы:** Гибрид

---

## Фаза 1 — Первые 30 дней: Ориентация

**Цели:**
- Понять, как строится роудмап продукта и как принимаются решения о приоритетах
- Изучить, как результаты пользовательских исследований попадают в планирование
- Задача результата: посетить 3 спринт-церемонии и написать сводку по каждой

**Ключевые контакты:**
| Имя / Роль | Цель | Когда |
|------------|------|-------|
| Руководитель продукта (менеджер) | Прояснить ожидания и критерии успеха | Неделя 1 |
| UX-исследователь | Изучить воркфлоу исследований и текущие проекты | Неделя 2 |
| Тимлид разработки | Понять технические ограничения, влияющие на роудмап | Недели 2–3 |
| Customer Success Manager | Изучить 3 ключевых сегмента клиентов | Недели 3–4 |

**Учебные вехи:**
- [ ] Завершить онбординг в Jira и Confluence (читать и создавать задачи)
- [ ] Изучить текущий роудмап и понять 3 активные инициативы
- [ ] Разобраться в воркфлоу исследований: как проводятся и как используются результаты
- [ ] Описать 3 ключевых сегмента клиентов с 2–3 характеристиками каждого

**Критерий успеха:** Может самостоятельно описать процесс построения роудмапа и рассказать о 3 текущих инициативах без подсказки менеджера.
```

### Пример 2: Senior Backend Engineer (удалённо)

**Ввод:**
```
Роль: Senior Backend Engineer, уровень: Senior
Формат: Удалённо
Приоритеты: изучить архитектуру сервисов, разобраться в on-call ротации и процессе инцидент-реагирования, освоить CI/CD пайплайн, понять модели данных ключевых сервисов, посещать code review команды
```

**Вывод (фрагмент — Фаза 1):**
```markdown
# План адаптации: Senior Backend Engineer — Новый сотрудник

**Дата выхода:** TBD
**Формат работы:** Удалённо

---

## Фаза 1 — Первые 30 дней: Ориентация

**Цели:**
- Составить карту сервисной архитектуры и понять, какими сервисами владеет команда
- Изучить правила on-call ротации и процесс реагирования на инциденты
- Задача результата: написать 2 содержательных code review с конкретными комментариями

**Ключевые контакты:**
| Имя / Роль | Цель | Когда |
|------------|------|-------|
| Engineering Manager | Прояснить ожидания и критерии успеха | Неделя 1 (онлайн) |
| Тимлид | Разобраться в архитектуре и компонентах команды | Недели 1–2 (асинхронно + синхронно) |
| On-call Buddy | Изучить процесс передачи смены и on-call плейбук | Недели 2–3 (асинхронно) |
| Senior Engineer (смежная команда) | Понять зависимости между сервисами | Недели 3–4 (онлайн) |

**Учебные вехи:**
- [ ] Прочитать документацию по архитектуре и составить карту зависимостей сервисов команды
- [ ] Изучить CI/CD пайплайн: как запускаются деплои и как происходит откат
- [ ] Посетить 3 code review и усвоить стандарты ревью команды
- [ ] Прочитать runbook по инцидент-реагированию и on-call плейбук

**Критерий успеха:** Может описать сервисы команды и их потоки данных любому члену команды без подготовки.
```
