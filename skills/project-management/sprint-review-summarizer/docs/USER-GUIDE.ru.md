# Руководство пользователя: Sprint Review Summarizer

Как превратить заметки по спринту в структурированный документ для стейкхолдеров без какой-либо настройки.

---

## Быстрый старт

Самый короткий путь к готовому документу:

1. Напишите или скопируйте заметки по спринту (любой формат — списки, абзацы, смешанный)
2. Напишите: "Итоги спринта" и вставьте заметки
3. Получите markdown-документ с четырьмя разделами и резюме

**Результат:** Структурированный документ, готовый к отправке стейкхолдерам.

**Время:** ~2 минуты

---

## Сценарии

### Сценарий 1: Подготовка к встрече sprint review

**Ситуация:**
Вы продакт-менеджер, и через 30 минут sprint review. Ваши заметки по последним двум неделям — разрозненные bullet points в блокноте. Вам нужен чистый документ для стейкхолдеров: что сделано, что перенесено, что дальше. Но времени на ручное форматирование нет.

**Что делать:**

1. Соберите заметки по спринту
   - Откройте заметки, PM-инструмент или любое место, где вы вели трекинг
   - Скопируйте всё релевантное: выполненные задачи, перенесённые, блокеры, приоритеты

2. Напишите: "Итоги спринта" и вставьте заметки
   - Вставьте всё одним блоком — порядок не важен
   - Добавьте контекст, если есть: номер спринта, название команды, даты

3. Просмотрите сгенерированный документ
   - Проверьте **Резюме** — метрика выполнения соответствует вашим ожиданиям?
   - Убедитесь, что задачи распределены по правильным разделам
   - При необходимости добавьте недостающие детали вручную

4. Используйте документ на встрече
   - Поделитесь экраном и пройдитесь по разделам сверху вниз
   - Используйте раздел **Фокус следующего спринта** как переход к планированию

**Ожидаемый результат:**

Вы получаете чистый markdown-документ со всеми четырьмя разделами, резюме ("6 из 8 задач выполнены; 2 перенесены") и ключевыми решениями, если они были в заметках. Вставляете в свой митинг-док и проводите встречу.

**Почему это работает:** Вместо 20 минут форматирования заметок вы получаете структурированный документ за секунды. Подготовка к встрече занимает 5 минут вместо 30.

### Сценарий 2: Еженедельный апдейт стейкхолдерам после закрытия спринта

**Ситуация:**
Вы скрам-мастер. Спринт закрылся вчера. Руководство ждёт письменный апдейт до конца дня: что сделала команда, что не успела, что дальше. У вас есть сырые заметки от команды — но они не подходят для коммуникации с топ-менеджментом.

**Что делать:**

1. Соберите заметки от команды
   - Попросите каждого участника написать 2–3 bullet points по итогам спринта
   - Объедините все заметки в один текстовый блок

2. Напишите: "Оформи итоги спринта" или "Преобразуй заметки спринта в отчёт"
   - Вставьте объединённые заметки
   - Добавьте номер спринта и даты, если они у вас есть

3. Просмотрите и отредактируйте результат
   - Скил автоматически сгенерирует документ с четырьмя разделами
   - Проверьте раздел **Риски и проблемы** — подходит ли язык для аудитории руководства?
   - Добавьте стратегический контекст, который скил не мог вывести из заметок

4. Отправьте стейкхолдерам
   - Скопируйте markdown в email-клиент или Notion
   - Отправьте как официальный итог спринта

**Ожидаемый результат:**

Вы получаете документ, структурированный под запросы руководства: одна строка-резюме, чёткие разделы, фокус следующего спринта. Руководство получает нужный контекст без необходимости читать сырые командные заметки.

**Почему это работает:** Скил конвертирует неотшлифованные заметки команды в структуру, понятную топ-менеджменту. Не нужно переписывать — только проверить и отправить.

### Сценарий 3: Сделать видимыми перенесённые задачи для руководства

**Ситуация:**
Вы тимлид и замечаете, что одни и те же задачи раз за разом оказываются в статусе "не сделано". Вы хотите создать документ по итогам спринта, который наглядно покажет перенесённые задачи и причины — без ощущения хаоса или провала.

**Что делать:**

1. Напишите заметки с явными причинами переноса
   - Пример: "Платёжная интеграция перенесена — документация API вендора всё ещё отсутствует"
   - Блокеры укажите отдельными пунктами в разделе Риски

2. Напишите: "Создай документ по итогам спринта" и вставьте заметки
   - Скил автоматически выделит перенесённые задачи с причинами

3. Проверьте разделы **Перенесено** и **Риски и проблемы**
   - Убедитесь, что причины переноса зафиксированы понятно
   - Проверьте, что **Фокус следующего спринта** отражает план по работе с перенесёнными задачами

4. Поделитесь с руководством
   - Документ показывает перенесённые задачи с контекстом — это делает паттерн видимым без обвинений
   - Используйте раздел **Риски** для эскалации блокеров, требующих управленческого решения

**Ожидаемый результат:**

Вы получаете документ, где перенесённые задачи появляются с причинами, а риски вынесены отдельно. Руководство видит чёткую картину того, что блокирует команду — а не просто список невыполненных задач.

**Почему это работает:** Перенесённые задачи с причинами рассказывают историю. Документ превращает блокеры в точки эскалации, а не необъяснённые пробелы.

## Советы

### Совет 1: Используйте сигнальные слова для точной классификации

Скил классифицирует задачи по ключевым словам. Чёткие сигнальные слова дают более точный результат:
- Выполнено: "сделали", "выпустили", "запустили", "исправили", "закрыли"
- Перенесено: "перенесли", "сдвинули", "не успели", "ушло в следующий спринт"
- Риски: "заблокировано", "риск", "зависимость", "проблема", "беспокоит"
- Следующий спринт: "следующий спринт", "дальше", "план на следующий", "приоритет"

**Совет профи:** Если задача попала не в тот раздел, добавьте в исходные заметки более чёткое сигнальное слово и запустите скил снова. Занимает 30 секунд.

### Совет 2: Добавьте метаданные для аккуратного заголовка

Если в заметках есть номер спринта, название команды и даты, скил использует их в заголовке документа. Даже одна строка "Спринт 24, 5–19 мая, Команда платформы" в начале заметок даёт профессиональный вид.

**Совет профи:** Создайте шаблон заметок с предзаполненной строкой метаданных. Копируйте его в начале каждого спринта и обновляйте по ходу работы.

### Совет 3: Пустые разделы — это тоже сигнал

Скил всегда генерирует все четыре раздела, даже если некоторые пустые. Пустой раздел **Перенесено** и пустой раздел **Риски** — хороший знак: спринт прошёл ровно. Наоборот, если **Перенесено** заполнен, а **Выполнено** короткий — документ делает это видимым с первого взгляда.

**Совет профи:** Делитесь документом с командой после каждого спринта. Формат из четырёх разделов создаёт постоянную точку отсчёта для обсуждения на ретроспективе.
