# Sprint Review Summarizer

Превратите сырые заметки по спринту в структурированный документ для стейкхолдеров за секунды — без Jira, YAML или интеграций.

---

## Обзор

Sprint Review Summarizer преобразует заметки на свободном языке в структурированный документ с четырьмя разделами: выполненные задачи, перенесённые задачи, риски и проблемы, фокус следующего спринта. Скил читает любой текст или markdown-файл и формирует готовый stakeholder-апдейт с резюме и метрикой выполнения. Используйте этот скил при подготовке к sprint review, составлении еженедельного статуса после спринта или конвертации черновых PM-заметок в структурированный отчёт.

---

## Требования

- Заметки по спринту в виде вставленного текста или markdown-файла (любая структура)
  - Подходят маркированные списки, абзацы и смешанный формат
  - Специальная структура не требуется
- Опционально: номер спринта, название команды, даты, цель спринта (используются для метаданных)
- Внешние инструменты, плагины и интеграции не нужны

---

## Как использовать

1. **Соберите заметки по спринту**
   - Напишите свободный итог спринта или используйте уже готовые заметки
   - Список задач, абзацы или смешанный формат — всё подходит

2. **Запустите скил фразой:**
   - "Итоги спринта" или "Оформи итоги спринта"
   - На английском: "Sprint review summary" или "Summarize sprint results"

3. **Предоставьте заметки**
   - Вставьте текст прямо в чат
   - Или укажите путь к локальному файлу при работе в Cowork

4. **Просмотрите документ для стейкхолдеров**
   - Получите markdown-документ со всеми четырьмя разделами и резюме
   - Скопируйте в email, Slack или проектную вики

## Примеры

### Пример 1: PM-заметки по итогам спринта

**Входные данные:**
```
Спринт 24, 5–19 мая, Продуктовая команда

Выпустили новый онбординг-флоу — все 3 экрана в проде.
Исправили баг логина, который блокировал мобильных пользователей.
Дашборд аналитики перенесли на следующий спринт — дизайн не успел.
Застряли на платёжной интеграции — документация вендора API устарела.
Следующий спринт: платёжная интеграция и запуск A/B-теста.
Решение: договорились перенести релиз v2 на неделю, чтобы доработать онбординг.
```

**Результат:**
```markdown
## Sprint Review: Спринт 24

**Команда:** Продуктовая команда
**Даты спринта:** 5–19 мая
**Резюме:** 2 из 3 задач выполнены; 1 перенесена из-за задержки дизайна; платёжная интеграция заблокирована вендором.

---

### ✅ Выполнено
- Новый онбординг-флоу — все 3 экрана в продакшне
- Исправление бага логина — мобильные пользователи разблокированы

### ⏩ Перенесено
- Дашборд аналитики — дизайн не успел; перенесён на следующий спринт

### ⚠️ Риски и проблемы
- Платёжная интеграция заблокирована: документация API вендора устарела

### 🎯 Фокус следующего спринта
- Платёжная интеграция
- Запуск A/B-теста

### 📋 Ключевые решения
- Релиз v2 перенесён на неделю для доработки онбординга
```

---

### Пример 2: Минимальные заметки без структуры

**Входные данные:**
```
Поиск сделали. Нотификации ещё не готовы. Главный риск — лимиты API стороннего сервиса. Далее: дофайнить нотификации и начать страницу настроек.
```

**Результат:**
```markdown
## Sprint Review: Спринт 2026-05-15

**Команда:** —
**Даты спринта:** —
**Резюме:** Основная цель спринта достигнута; 1 задача перенесена; зафиксирован риск лимитов API.

---

### ✅ Выполнено
- Поиск

### ⏩ Перенесено
- Нотификации — не завершены в этом спринте

### ⚠️ Риски и проблемы
- Лимиты API стороннего сервиса могут повлиять на дальнейшую работу

### 🎯 Фокус следующего спринта
- Дофайнить нотификации
- Начать страницу настроек

*(Исходные заметки были минимальными — документ может быть неполным. Рекомендуется добавить детали перед отправкой.)*
```
