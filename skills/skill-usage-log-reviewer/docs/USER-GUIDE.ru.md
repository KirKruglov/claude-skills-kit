# Skill Usage Log Reviewer — Руководство пользователя

Как проверить коллекцию скилов Claude и поддерживать её в порядке.

---

## Быстрый старт

Самый быстрый способ проверить скилы:

1. Напишите: "Аудит скилов" и вставьте список имён установленных скилов
2. Ответьте на вопросы об использовании (ежедневно / еженедельно / ежемесячно / никогда)
3. Получите отчёт с вердиктами Оставить / Пересмотреть / Деактивировать и готовым чеклистом

**Результат:** Структурированная таблица — какие скилы удалить и почему.

**Время:** ~5 минут

---

## Сценарии использования

### Сценарий 1: Ежемесячная чистка портфолио

**Ситуация:**
За последние два месяца вы добавляли скилы и теперь установлено 15 и более. Сессии в Claude кажутся перегруженными — список скилов длинный, и вы подозреваете, что половину никогда не вызывали. Хотите быстро почистить коллекцию перед началом нового проекта.

**Что делать:**

1. Откройте настройки Claude и скопируйте список активных скилов
   - В Cowork скилы видны в боковой панели или в настройках плагинов
   - Достаточно скопировать имена — описания не нужны

2. Активируйте скил: "Аудит скилов"
   - Вставьте имена скилов по запросу
   - Если есть быстрые заметки об использовании — добавьте их сразу (например, "skill-x — ни разу не использовал")

3. Ответьте на вопросы об использовании
   - Скил спросит о частоте использования группами по 5–8 скилов
   - Будьте честны — "никогда не использовал" — самый полезный ответ

4. Изучите отчёт аудита
   - Начните с раздела ❌ Деактивировать — их можно удалить сразу
   - Для позиций ⚠️ Пересмотреть решите, были ли они вам нужны в прошлом месяце

5. Деактивируйте помеченные скилы
   - Зайдите в Настройки Claude → Плагины/Скилы
   - Удалите каждый скил из Чеклиста деактивации

**Ожидаемый результат:**

Вы получите отчёт с точным указанием, какие скилы не используются и почему. Чеклист деактивации — готовый список для действий: откройте настройки и удалите каждый пункт. В типичной коллекции из 15 скилов обычно находится 4–6 кандидатов на деактивацию.

**Почему это работает:** Каждый установленный скил добавляет токены в каждую сессию через системный промпт. Удаление 5 неиспользуемых скилов экономит 500–1 500 токенов за сессию — быстрее ответы, больше места для реальной работы.

### Сценарий 2: Аудит после установки плагина

**Ситуация:**
Вы только что установили новый пакет плагинов (например, "product-management" или "engineering"), который добавил сразу 8 новых скилов. Неясно, какие из них пригодятся, а запускать все 8 бессрочно не хочется. Нужна быстрая сортировка сразу после установки.

**Что делать:**

1. Запишите имена новых скилов
   - После установки плагина отметьте, какие скилы появились
   - Можно оценивать только новые скилы или весь список — как удобнее

2. Активируйте скил: "Проверь мои установленные скилы" или "Какие скилы деактивировать"
   - Вставьте список новых скилов (или полный список)

3. Опишите, для чего установили плагин
   - Укажите свой контекст (например, "я PM, установил плагин для планирования роадмапа")
   - Скил сопоставит назначение каждого скила с вашим кейсом

4. Получите отчёт-сортировку
   - Скилы, соответствующие вашему кейсу → ✅ Оставить
   - Скилы вне вашей роли или workflow → ❌ Деактивировать сразу

**Ожидаемый результат:**

Фокусный отчёт: из 8 новых скилов 2–4 окажутся реально нужными; остальные можно деактивировать до востребования.

**Почему это работает:** Пакеты плагинов рассчитаны на широкую аудиторию. PM не нужны все инженерные скилы, а разработчику — финансовые. Сортировка сразу после установки делает коллекцию роль-специфичной с первого дня.

### Сценарий 3: Квартальная ревизия коллекции

**Ситуация:**
Вы используете Claude 6 месяцев, и список скилов рос органически. Какие-то были полезны в первом квартале, но сейчас уже неактуальны. Нужна структурированная квартальная проверка, чтобы привести портфолио скилов в соответствие с текущими приоритетами.

**Что делать:**

1. Экспортируйте полный список скилов
   - Просмотрите все установленные скилы и выпишите их
   - Добавьте краткую пометку: когда примерно последний раз использовали

2. Активируйте скил: "Обзор использования скилов"
   - Предоставьте полный список с заметками

3. Изучите результат обнаружения дубликатов
   - Скил выявит пары с пересекающимся назначением (например, два скила для подготовки к встречам)
   - Решите, какой из каждой пары лучше подходит для текущего workflow

4. Используйте раздел Заметки отчёта
   - Проверьте наблюдения по всей коллекции (например, "У вас 4 скила для встреч — оставьте 1–2")
   - Установите для себя лимит активных скилов (например, не более 10)

**Ожидаемый результат:**

Полный квартальный снимок портфолио скилов — что активно, что устарело, что дублируется. Отчёт можно сохранить как запись состояния коллекции на конкретную дату.

**Почему это работает:** Квартальные ревизии предотвращают постепенное разрастание. Без структурированного аудита коллекции растут бесконечно. Личный лимит (например, 10 активных скилов) и ежеквартальная проверка поддерживают сессии быстрыми и сфокусированными.

## Советы

### Совет 1: Говорите прямо о "никогда не использовал"

Самая ценная информация — честность насчёт скилов, которые вы никогда не вызывали. Не оставляйте скил только потому, что он казался полезным при установке. Если не использовали 30 дней — смело отвечайте "никогда" — скил порекомендует деактивацию. Переустановить его можно за 30 секунд.

**Лайфхак:** Деактивация не удаляет скил навсегда — она просто убирает его из активного контекста сессии.

### Совет 2: Проводите аудит новых скилов через 2 недели после установки

Лучший момент для проверки скила — через 2 недели после установки. За это время вы успели попробовать его, но ещё помните, зачем устанавливали. Ждать месяцами — значит потом мучительно вспоминать, использовали ли вы скил хоть раз.

### Совет 3: Используйте отчёт как лог портфолио скилов

Сохраняйте `skill-audit-report.md` с датой в имени файла (например, `skill-audit-2026-05.md`) и храните по одному файлу за квартал. Со временем это станет личным логом эволюции вашего использования скилов — полезно для принятия решений о новых установках и понимания, какие категории скилов вы реально применяете.
