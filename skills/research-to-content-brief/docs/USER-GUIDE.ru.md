# Research to Content Brief — Руководство пользователя

Как превратить папку с research-заметками в структурированный контент-бриф.

---

## Быстрый старт

Самый короткий путь к контент-брифу:

1. Сложите research-заметки в папку (или скопируйте их в чат)
2. Скажите: "Составь контент-бриф из заметок" и укажите путь к папке или вставьте контент
3. Опционально добавьте: "для блог-поста" (или для лендинга, соцсетей, email)
4. Получите `content-brief.md` — готов для передачи автору

**Результат:** Структурированный бриф с разделами Аудитория, Ключевое сообщение, Контент-углы, Конкурентная дифференциация, Трендовые зацепки, Рекомендуемые форматы.

**Время:** ~3 минуты

---

## Сценарии

### Сценарий 1: Брифинг автора после исследовательского спринта

**Ситуация:**
Вы контент-маркетолог. За прошлую неделю накопилось 5 research-файлов: заметки из пользовательских интервью, наблюдения за лендингами конкурентов, тренды из отраслевых рассылок. Автор ждёт бриф, но времени вручную синтезировать все заметки нет.

**Что делать:**

1. Сложите все 5 файлов в одну папку
   - Названия файлов могут быть любыми — скил категоризирует их автоматически
   - Микс заметок об аудитории, конкурентных сигналов и трендов — это норма

2. Запустите скил: "Составь контент-бриф из заметок — папка /research/q2/"
   - Скил прочитает и категоризирует все файлы
   - Извлечёт боли аудитории, пробелы конкурентов и трендовые зацепки

3. Опционально уточните формат:
   - Добавьте "для блог-поста" — получите углы под длинный формат
   - Или "для лендинга" — получите формулировки, ориентированные на ценностное предложение

4. Проверьте бриф и заполните помеченные разделы:
   - Разделы "NEEDS MANUAL INPUT" означают отсутствие исходных данных — добавьте их вручную
   - Контент-углы будут опираться на ваши исследования, а не на шаблонные советы

5. Передайте бриф автору как техзадание на создание контента

**Ожидаемый результат:**

Вы получаете `content-brief.md` с:
- Разделом Аудитория из ваших интервью-заметок
- Ключевым сообщением, синтезированным из болей и дифференциации
- 2–3 контент-углами, основанными на реальных исследованиях
- Конкурентной дифференциацией, показывающей пробелы конкурентов
- Трендовыми зацепками со ссылками на исходные файлы

Автор получает полный бриф и не задаёт уточняющих вопросов.

**Почему это работает:** Вместо ручного синтеза 5 файлов (30+ минут) скил читает и извлекает всё за секунды, давая черновой бриф, который можно доработать за 5 минут.

### Сценарий 2: Самостоятельная подготовка перед написанием контента

**Ситуация:**
Вы продукт-маркетолог и пишете контент сами. Есть папка с заметками по конкурентному анализу двухнедельной давности — но всё уже подзабылось. Нужен быстрый освежитель и план контента перед тем, как садиться писать.

**Что делать:**

1. Укажите путь к папке с заметками по конкурентному анализу или вставьте их
   - Даже один смешанный файл подойдёт

2. Скажите: "Создай контент-бриф из папки с исследованиями — для соцсетей"
   - Скил подстроит углы и рекомендации форматов под соцсети

3. Изучите раздел Контент-углы:
   - Это зацепки, которые будут использоваться в постах
   - Каждая опирается на исследования с ратиональным обоснованием

4. Изучите раздел Конкурентная дифференциация:
   - Показывает, что конкуренты НЕ говорят — это ваша возможность занять нишу

5. Используйте бриф как ориентир при написании:
   - Ключевое сообщение = тезис, к которому возвращаетесь
   - Контент-углы = зацепки для постов или введения параграфов
   - Тренды = актуальный повод публиковать сейчас, а не потом

**Ожидаемый результат:**

Вы получаете бриф-ориентир: Аудитория — чтобы не терять фокус, Ключевое сообщение — чтобы держаться темы, Контент-углы — чтобы сохранять разнообразие, Тренды — чтобы быть актуальным.

**Почему это работает:** Спустя две недели после спринта ключевые инсайты размываются. Бриф вытаскивает топовые сигналы из заметок, чтобы вы писали на основе данных, а не наугад.

### Сценарий 3: Синтез смешанных заметок без структурированной папки

**Ситуация:**
Вы фриланс-контент-стратег. Всё ваше исследование — один большой md-файл: цитаты аудитории, наблюдения за конкурентами и тренды вперемешку. Через 20 минут клиентский звонок, нужен бриф.

**Что делать:**

1. Откройте смешанный файл с заметками и скопируйте содержимое

2. Вставьте в чат и скажите: "Преобразуй research-заметки в бриф"
   - Скил автоматически категоризирует контент по ключевым словам
   - Вы увидите, что было отнесено к заметкам об аудитории, конкурентам или трендам

3. Проверьте раздел покрытия источников внизу брифа:
   - Убедитесь, что категоризация совпадает с вашим замыслом
   - Если заметка определена неверно — запустите повторно с явными метками ("Это данные о конкурентах:")

4. Используйте бриф на клиентском звонке:
   - Аудитория = кого вы таргетируете (подтвердите с клиентом)
   - Контент-углы = предложенные зацепки для контента (питчуйте 2–3, получайте обратную связь)
   - Конкурентная дифференциация = почему их контент будет выделяться

**Ожидаемый результат:**

Вы получаете черновой бриф за 3 минуты — достаточно структурированный для продуктивного звонка, с разделами "NEEDS MANUAL INPUT", которые подскажут, что уточнить у клиента.

**Почему это работает:** Даже беспорядочные смешанные заметки превращаются в рабочий бриф. Автокатегоризация охватывает 80% материала, а флаги "NEEDS MANUAL INPUT" показывают точные пробелы.

## Советы

### Совет 1: Размечайте типы заметок для точной категоризации

Если файлы содержат смешанный контент, добавьте простой заголовок для каждого блока:
```
## Наблюдения об аудитории
...

## Конкурентные сигналы
...
```
Это помогает скилу категоризировать точнее и быстрее. Без меток работают ключевые слова — но явные метки надёжнее.

### Совет 2: Указывайте целевой формат для более точных углов

Добавление "для блог-поста" или "для лендинга" меняет то, как скил формулирует Контент-углы:
- **Блог-пост** → нарративные зацепки, структура проблема-решение
- **Лендинг** → ценностные предложения, работа с возражениями
- **Соцсети** → ёмкие углы, паттерн-прерыватели, встроенные CTA
- **Email** → зацепки для темы письма, личная интонация

Без указания формата — общие углы. С ним — углы под конкретный жанр.

### Совет 3: Используйте разделы "NEEDS MANUAL INPUT" как чеклист пробелов

Если раздел помечен — значит, в папке нет данных по этому аспекту. Перед брифингом автора решите: "Важен ли этот раздел для данного материала?" Если да — найдите недостающие данные. Если нет — скажите автору пропустить его. Флаг — это подсказка, а не ошибка.
