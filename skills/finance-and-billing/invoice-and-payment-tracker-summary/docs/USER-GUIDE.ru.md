# Invoice & Payment Tracker Summary — Руководство пользователя

Как получить полную aging-сводку, акт сверки по клиентам и список «требует внимания» из ваших данных по счетам за несколько минут.

---

## Быстрый старт

Самый быстрый способ получить сводку:

1. Скопируй список счетов из таблицы или заметок (любой формат)
2. Напиши: «Aging-сводка по счетам» и вставь данные
3. Получи трёхчастный отчёт: таблица старения, акт сверки по клиентам, список «требует внимания»

**Результат:** Полный снапшот дебиторской задолженности, который можно отправить бухгалтеру или использовать в разговоре о cash flow.

**Время:** ~2 минуты

---

## Сценарии

### Сценарий 1: Ежемесячная проверка дебиторки перед встречей с бухгалтером

**Ситуация:**
Ты — фрилансер или владелец малого бизнеса, готовишься к ежемесячной встрече с бухгалтером. У тебя 10–15 счетов в разных состояниях: одни оплачены, другие частично, несколько просрочены. Бухгалтер хочет знать текущую позицию по дебиторке. Данные есть в таблице, но специализированного ПО для aging-отчёта нет.

**Что делать:**

1. Открой таблицу со счетами и скопируй нужные строки
   - Включи: номер счёта, имя клиента, дату, сумму, оплаченную сумму (или статус)
   - Если есть даты оплаты (due date) — включи их: это даёт точный расчёт просрочки

2. Активируй скилл фразой: «Aging-сводка по счетам» или «Кто из клиентов не заплатил?»
   - Вставь скопированные данные
   - Если заголовки неоднозначны, скилл попросит подтвердить маппинг перед генерацией

3. Просмотри трёхчастный вывод
   - **Таблица старения:** найди счета в бакетах 31–60 и 90+ дней — они требуют приоритетного внимания
   - **Акт сверки по клиентам:** передай этот раздел бухгалтеру как данные о состоянии расчётов
   - **Список «требует внимания»:** используй как повестку для встречи

4. Перешли отчёт бухгалтеру
   - Скопируй вывод в формате markdown и вставь в письмо или папку проекта
   - Бухгалтер получает именно те данные, которые нужны, — без необходимости разбирать таблицу

**Ожидаемый результат:**

Ты получаешь чистый отчёт:
- Каждый счёт со статусом, остатком и днями просрочки
- Разрез по клиентам (заменяет ручной трекинг «кто что должен»)
- Короткий список просроченных статей, отсортированных по срочности

**Почему это работает:** Вместо того чтобы строить сводную таблицу вручную, скилл структурирует сырые данные в профессиональный aging-отчёт меньше чем за две минуты.

### Сценарий 2: Еженедельная проверка cash flow в небольшом агентстве

**Ситуация:**
Ты управляешь небольшим агентством с 5–8 активными клиентами. Каждое утро в понедельник ты хочешь знать: кто заплатил за эту неделю, у кого скоро наступает срок оплаты и кто «затих» после наступления срока. Счета ведёшь в текстовом файле или Notion-таблице, а не в бухгалтерском ПО.

**Что делать:**

1. Скопируй данные по счетам за эту неделю
   - Включи все открытые счета (текущие и просроченные) и новые поступления оплаты
   - Подходит даже простой текстовый список: «Клиент А — СЧ-045 — 420 000 ₽ — до 15 июня — не оплачен»

2. Напиши: «Покажи статус моих счетов» и вставь данные

3. Сфокусируйся на списке «Требует внимания»
   - Список отсортирован по срочности (сначала наибольшая просрочка, затем наибольшая сумма)
   - Используй его, чтобы решить: с кем связаться сегодня, а кто подождёт до конца недели

4. Используй акт сверки по клиентам, чтобы проверить частичные оплаты
   - Если клиент частично заплатил на прошлой неделе, в акте сверки автоматически показывается остаток

**Ожидаемый результат:**

Утренний снапшот в понедельник:
- Все просроченные счета, ранжированные по срочности
- Чёткий остаток по каждому клиенту (включая частичные оплаты)
- Текущие счета отмечены как «не просрочены» — чтобы не предъявлять претензии раньше времени

**Почему это работает:** Aging-бакеты дают структурированный тираж: 90+ дней — звонить сегодня, 31–60 дней — письмо с напоминанием, 0–30 дней — наблюдение. Никаких формул в таблицах.

### Сценарий 3: Подготовка сводки дебиторки для партнёра или инвестора

**Ситуация:**
Ты — менеджер проектов в консалтинговой компании. Потенциальный партнёр или инвестор попросил сводку по дебиторской задолженности: кто должен, сколько и как давно. Сырые данные есть, но нужно представить их в чистом, структурированном виде — не показывать замусоренную таблицу.

**Что делать:**

1. Экспортируй или скопируй данные по счетам (из любого инструмента)
   - Включи: имена клиентов, суммы, даты оплаты и статус платежа

2. Напиши: «Сводка дебиторской задолженности» и вставь данные
   - Скилл обработает все счета и построит полный отчёт

3. Используй раздел «Акт сверки по клиентам» как основной артефакт для презентации
   - Для каждого клиента — чистая таблица в стиле акта сверки
   - Скопируй этот раздел в слайд, письмо или документ

4. Добавь таблицу старения как приложение
   - Она показывает полную картину с бакетами (0–30 / 31–60 / 61–90 / 90+) для быстрой оценки рисков

**Ожидаемый результат:**

Профессиональный отчёт по дебиторке:
- Итого к получению и распределение по aging-бакетам
- Акт сверки по каждому клиенту (аналог официального акта сверки расчётов)
- Список «требует внимания» для внутреннего использования

**Почему это работает:** Вывод отформатирован для внешнего использования — никаких сырых данных, формул и сводных таблиц. Можно вставить прямо в любой документ.

## Советы

### Совет 1: Включай даты оплаты для точного расчёта просрочки

Если в списке нет дат оплаты, скилл использует допущение net 30 (дата счёта + 30 дней) и помечает это в начале отчёта. Для точного расчёта укажи фактическую дату оплаты — особенно если условия платежа у разных клиентов различаются (net 15, net 45, net 60).

**Совет профессионала:** Если у некоторых клиентов индивидуальные условия, укажи их рядом с именем: «Acme Corp (net 60)» — скилл учтёт это при расчёте.

### Совет 2: Указывай частичные оплаты явно

Если клиент внёс частичный платёж, добавь колонку «Оплачено» или «Поступило» с фактической суммой — не просто статус «частично оплачен». Скилл использует точную сумму для расчёта остатка и покажет его в акте сверки по клиентам.

**Совет профессионала:** «СЧ-003 — 480 000 ₽ — оплачено 200 000 ₽» даст точный остаток 280 000 ₽, тогда как просто «частично оплачен» не позволяет рассчитать сумму.

### Совет 3: Для больших списков добавляй дату отчёта

Если вставляешь 20+ счетов, добавь дату отчёта в начале: «Дата отчёта: 22 июня 2026». Это привязывает расчёт просрочки к конкретной дате — важно, если ты формируешь отчёт за прошедший период или хочешь воспроизводимые результаты.

**Совет профессионала:** Можно задать общие условия глобально: «Все счета net 30, если не указано иное» — скилл применит это к счетам без даты оплаты.
