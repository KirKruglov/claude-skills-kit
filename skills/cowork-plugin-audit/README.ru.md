# Cowork Plugin Audit

Оставь только плагины, которые соответствуют твоему workflow — остальные отключи, чтобы снизить расход токенов и убрать лишний шум.

---

## Обзор

Cowork Plugin Audit анализирует установленные плагины Claude Cowork в контексте твоего рабочего процесса и формирует приоритизированную таблицу рекомендаций: оставить / отключить / отключить до следующего проекта. Каждый плагин классифицируется как core, contextual или idle с конкретным обоснованием. Дополнительно — качественная оценка потенциального снижения расхода токенов. Используй скил, когда сессии Cowork стали медленнее или дороже, после установки нескольких новых плагинов, при запуске проекта с другим фокусом, или при плановом ревью рабочего окружения.

---

## Требования

- Описание роли и 2–3 основных задач в Cowork (plain text)
- Список установленных плагинов (вставить из Cowork Настройки → Плагины)
- Опционально: файл контекста проекта (`.md`) — скил считает его автоматически, если он есть

Дополнительные инструменты не нужны.

---

## Как использовать

1. **Опиши свой workflow**
   - Подготовь 2–3 предложения: роль и основные задачи в Cowork
   - Пример: «Я продакт-менеджер. Пишу спеки, провожу спринт-планирования, смотрю метрики. Не работаю с кодом и продажами.»

2. **Запусти скил**
   - Напиши: «Аудит плагинов» или «Какие плагины отключить»
   - Или по-английски: «Audit my plugins» или «Cowork plugin audit»

3. **Предоставь список плагинов**
   - Вставь список установленных плагинов по запросу
   - Если не знаешь точных названий, скил предложит стандартный список

4. **Изучи таблицу аудита**
   - Каждый плагин получает категорию (core / contextual / idle) и рекомендацию (keep / disable / disable-until-needed)
   - Итоговый блок — счётчики и оценка снижения токен-расхода

5. **Примени рекомендации**
   - Отключи указанные плагины в настройках Cowork
   - Опционально: скопируй сгенерированный блок Project Instructions, чтобы плагины не реактивировались автоматически

## Примеры

### Пример 1: Продакт-менеджер чистит окружение после онбординга

**Ввод:**
```
Роль: продакт-менеджер. Пишу спеки, провожу спринт-планирования, смотрю метрики.
Продажами, разработкой и финансами не занимаюсь.

Установленные плагины: product-management, engineering, sales, data, finance, skill-planner
```

**Вывод:**
```
### Контекст workflow
Продакт-менеджер: спеки, спринт-планирование, ревью метрик.

### Таблица аудита

| Плагин             | Категория   | Рекомендация         | Обоснование                                           |
|--------------------|-------------|----------------------|-------------------------------------------------------|
| product-management | core        | keep                 | Спеки и спринт-планирование — основные задачи         |
| data               | core        | keep                 | Ревью метрик требует аналитических инструментов       |
| skill-planner      | contextual  | disable-until-needed | Полезен для исследования скилов, но не ежедневно      |
| engineering        | idle        | disable              | Разработка не упоминается в описании workflow         |
| sales              | idle        | disable              | Продажи не упоминаются в описании workflow            |
| finance            | idle        | disable              | Финансовых задач нет в описании workflow              |

### Итог
- Оставить: 2 | Отключить: 3 | Отключить до следующего: 1
- Ожидаемый эффект: умеренное снижение токен-расхода
```

---

### Пример 2: Разработчик с минимальным набором плагинов

**Ввод:**
```
Роль: бэкенд-разработчик. Пишу код, дебажу, ревьюю PR, пишу техническую документацию.

Установленные плагины: engineering, product-management
```

**Вывод:**
```
### Контекст workflow
Бэкенд-разработчик: разработка, дебаггинг, код-ревью, документация.

### Таблица аудита

| Плагин             | Категория  | Рекомендация | Обоснование                                            |
|--------------------|------------|--------------|--------------------------------------------------------|
| engineering        | core       | keep         | Разработка, дебаггинг, ревью — основные задачи         |
| product-management | contextual | keep         | Документация пересекается со скилами PM-плагина         |

### Итог
- Оставить: 2 | Отключить: 0 | Отключить до следующего: 0
- Изменений не рекомендуется
```

| Reduce token usage from plugins  | Снизь расход токенов на плагины      |
